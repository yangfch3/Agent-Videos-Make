# 技术选型与输出规格

各层工具、音效来源、画质与输出规格的默认方案。环境版本见 [README](../README.md)，用法与坑见[工程约定](工程约定.md)。

## 1. 分层与选定

讲解类画面多为示意图，只有少数镜头要展示真实 GPU 效果，所以按层选型：

| 层 | 选定 | 说明 |
|---|---|---|
| 合成与文字 | HyperFrames（HTML · SVG · GSAP） | 文字一律走这一层，从文本表读取；动态文字排版是 HTML + GSAP 的强项 |
| 示意图 | HyperFrames 为主 | Manim 只出公式与少量示意图，不排中文，以透明片段导入 |
| 真实效果 | WebGPU（合成内渲染） | 原生图形 API 离线渲染作补充；透明片段用 MOV 内 PNG（无损 RGBA） |
| 3D 示意、剧情 | HyperFrames + Three.js | 渲染时关闭 fast-capture，以保证确定性 |

- 备选：HyperFrames 碰壁时用 Remotion（React/TS；个人及 ≤ 3 人公司免费，超出付费），镜头内 WebGPU 代码基本可迁移
- 不作主力：Blender（重，只适合片头 / 氛围镜头）、Godot（场景文件 AI 不易编辑）

## 2. HyperFrames 要点

- HTML 合成 → headless Chrome 逐帧 seek → FFmpeg 编码，同输入同视频（[heygen-com/hyperframes](https://github.com/heygen-com/hyperframes)）
- 画面须为时间 t 的纯函数：不用 `Math.random()`、`requestAnimationFrame`、`performance.now()`；有状态的模拟须能从任意 t 重建
- GSAP 时间线在任何 `await` 之前同步注册
- WebGPU：合成根节点加 `data-requires-webgpu`，捕获前须成功创建 device（只有 adapter 不算），10 秒内失败即报错，不静默降级；默认要求硬件 adapter
- CanvasDrawElement + WebGPU 组合（如 liquid-glass 区块）自带 headless shell 不支持，需经 `PRODUCER_HEADLESS_SHELL_PATH` 指定 Brave / Chrome Canary

### WebGPU 能力边界

- 有：compute、storage buffer、原子操作、workgroup 共享内存、storage texture、间接绘制 / dispatch、逐目标独立混合、rgba16float 渲染与混合、MSAA（采样数 1 或 4）
- 无：几何着色器、曲面细分、`CLAMP_TO_BORDER`、持久映射、核心规范的 multi-draw-indirect
- 着色语言为 WGSL

## 3. 音效与音乐

画面由脚本生成，事件时刻已知，音效落点直接绑定画面事件，不靠「看视频对齐」。

| 方案 | 适用 | 许可 |
|---|---|---|
| 程序化合成（numpy，基础件在 `shared/py/common.py`） | 提示音、与数据绑定的音效（如数值 → 音高） | 自有代码 |
| [Stable Audio 3 Small-SFX](https://huggingface.co/stabilityai/stable-audio-3-small-sfx) | 写实质感音效；433M，官方标注 CPU 可跑 | Stability AI Community License：年收入 < 100 万美元可免费商用（[来源](https://stability.ai/license)） |
| 素材库（Kenney CC0、Freesound 按文件筛 CC0） | 兜底 | 逐文件确认 |

- 程序化为主、Stable Audio 补写实；生成时固定种子，非生成的 WAV 存入项目作资产（LFS）
- 不建议：Stable Audio 3 Medium（需 Flash Attention 2，Windows 安装风险）、MMAudio（权重 CC-BY-NC 4.0，不可商用）
- 是否带背景音乐由每部片或系列定。自带时两种做法：首尾无缝的循环段平铺（`shared/py/loopbgm.py`）；整曲按镜头写，换场落在小节线上，与画面更贴合
- 平台曲库授权一般限站内使用，商业推广以平台规则为准

## 4. 画质与编码

- 平台会二次压缩：避免 1px 细线、密集网格、满屏高频噪点
- yuv420p 下深色底上的彩色细字易糊，注意描边与亮度对比；确认 BT.709 转换不发灰偏色
- 线条与文字用 MSAA 或 2× 超采样；快动用子帧累积做运动模糊
- 横屏视频在手机竖屏信息流里显示更小，最小字号按此校准；避开进度条、弹幕、标题栏遮挡区
- 光敏安全参考 WCAG 2.3.1，任意 1 秒内闪烁不超过 3 次

## 5. 输出规格

只出一份平台无关的母版，各平台上传同一文件。

| 项 | 取值 |
|---|---|
| 分辨率 | 1920×1080，横屏 16:9 |
| 帧率 | 60fps（需要 30fps 时隔帧抽取） |
| 编码 | MP4（faststart），H.264 High，yuv420p，BT.709 limited range，逐行 |
| 码率 | x264 CRF ≈ 16 的 VBR；参考 YouTube 1080p60 建议 12 Mbps |
| 音频 | AAC-LC，48 kHz，立体声，按 320 kbps 编码（ffmpeg 原生 AAC 遇稀疏音效时平均码率会低于此，属正常，不以实测码率判）；真峰值 ≤ −1 dBTP |

来源：[YouTube 上传编码建议](https://support.google.com/youtube/answer/1722171)
